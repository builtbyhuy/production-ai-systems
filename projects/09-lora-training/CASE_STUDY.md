# Case study — a trained adapter is not a quality result

The engineering goal was to make a training result inspectable: which source records reached optimization, which model revision was used, what weights changed, what adapter can be reloaded, and whether the held-out capabilities survived. A tiny locally initialized GPT-2 allowed real SFT and DPO execution under a small CPU allocation without downloading model weights.

The smoke trained 1,024 adapter parameters attached to a 39,456-parameter random model for three steps per stage. It exercised the actual named libraries, recorded optimizer checkpoints, demonstrated changed LoRA tensors and unchanged SFT backbone tensors, and reloaded both adapters with exactly matching probe logits. SFT loss was 5.716662; DPO loss was 0.692596. The recorded pipeline after imports/setup took 1.182 seconds. The exact dependency versions and model/data artifact hashes are retained in `artifacts/p09-smoke`.

That success was strictly mechanical. All twelve held-out questions remained incorrect at base, SFT and DPO stages. Small NLL reductions did not become correct answers. The model had random weights, a vocabulary fitted to training examples only, and six held-out cases per suite. The predeclared release gate required twenty and rejected promotion. This is useful negative evidence: the pipeline demonstrated optimization while refusing to label it useful fine-tuning.

Two design choices prevent misleading comparisons. First, DPO's reference is an independently frozen SFT policy. Disabling an adapter on the original base would silently change what DPO is regularizing against. Second, both stages use the same source-disjoint held-out suites and identical hashes. A later evaluation cannot claim retention by quietly changing cases, sample counts or missing/nonfinite measurements.

Several tempting shortcuts were rejected: using a copied benchmark solution as training data, allowing a model installer to choose a multi-gigabyte CUDA stack, silently truncating a target sequence, treating a generated adapter file as proof of learning, or lowering the retention gate to fit the six available cases. Known P04 and P17 sources are explicitly excluded. General-domain rehearsal examples are mixed into training, but LoRA and rehearsal cannot guarantee freedom from forgetting elsewhere.

The present checkpoint policy is deliberately simple: a fixed final step count, selected before the run. Development examples are reserved but not used to choose a checkpoint. A substantive next experiment needs a suitable licensed pretrained snapshot, reviewed domain instructions and defensible preferences, a sufficiently powered capability suite, and a predeclared development-selection process. It must retain this smoke result as a separate record, even if later outcomes are better.
